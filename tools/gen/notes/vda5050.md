## VDA 5050 in this pack

VDA 5050 is the interface between a fleet control system and the mobile robots
(automated guided vehicles) it directs. A message is one JSON object, sent over MQTT on a
topic that names the interface, its major version, the manufacturer, the robot's serial
number and the message type. Eight packs are generated from the schemas of version 3.0.0,
one per message type (`tools/gen/vda5050-run.sh`): `vda5050-order`,
`vda5050-instant-actions`, `vda5050-zone-set` and `vda5050-responses` go from fleet
control to the robot; `vda5050-state`, `vda5050-visualization`, `vda5050-connection` and
`vda5050-factsheet` come from the robot or, for `connection`, from the broker on its
behalf. The topic is not part of the message.

Every message starts with the same header: `headerId` (a counter per topic),
`timestamp`, `version`, `manufacturer` and `serialNumber`. `timestamp` is bound to
`time_ms`, and its text is kept as a raw key as well. `serialNumber` is bound to `uid`.
The document calls the serial number unique, but a consumer that merges fleets from
several manufacturers should read it together with `manufacturer`, as the topic does.

**Positions are not bound to `lat` and `lon`.** Every position of VDA 5050 (the robot's
`mobileRobotPosition`, node positions, trajectory control points, zone vertices) is `x`
and `y` in metres, with `theta` in radians, in the project's own map coordinate system.
Each floor has a map with the same project origin, named by `mapId`. None of them is a
geodetic position, so no `geojson` or `cot-xml` vector is written. For the same reason
`theta` is not `course`, which is a heading from true north. The velocity (`vx`, `vy`,
`omega`) is in the robot's own frame, so it is not bound to `speed_ms` either.
