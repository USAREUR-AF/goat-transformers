Open source, Apache-2.0, pre-1.0

goat-transformers converts a message from any supported format to any other, and every format is a data file, not code.

A drone's 25-byte Remote ID broadcast becomes a Cursor on Target event for a tactical map and an NMEA 2000 position message for a ship's instrument network. No engine holds code for any of the three formats: each one is a pack, a text file with one line for each field.

Quick start: needs a Rust toolchain and nothing else
git clone https://github.com/USAREUR-AF/goat-transformers
cd goat-transformers/engines/rust && cargo build --release
echo 122624160b42bf241b6ed1b4b69808ac0870086b53150e0200 \
  | ./target/release/goat-xf convert --from remote-id --to cot-xml --packs-only remote-id,cot-xml

In: Remote ID Location message, 25 bytes (ASTM F3411)

--to cot-xml  Cursor on Target event, the XML that tactical map software reads

<event version="2.0" type="a-u-X"><point lat="45.539309" lon="-122.966389" hae="110" ce="9999999" le="9999999"/><detail/></event>

--to nmea2000  parameter group 129025, the position message of a ship's instrument network, 11 bytes: 01f80142bf241b6ed1b4b6

012345678910 01f80142bf241b6ed1b4b6 latlon

lat, lon and hae (height above the ellipsoid) are keys of the shared model. 9999999 is Cursor on Target's value for "not known". Both outputs are what goat-xf, the command-line tool, prints for this input.5

    What it is

    Formats are data. Engines are generic.

    A format is a data file

    A pack is a directory with a pack.def: the format's name, its wire type, the public document it was written from, and one field line for each value. A wire type is an engine's codec for a family of encodings; there are seven: bits, geojson, json, protobuf, text, tlv and xml. Adding a format whose wire type exists changes no engine.

    One shared model

    Every pack maps its fields to typed keys in fixed units: degrees, meters, meters per second, milliseconds since 1970. A conversion decodes the source message to the model and encodes the model to the target, so 2,531 formats need 2,531 packs, not 6,403,430 converters, one for each ordered pair.

    Seven engines that must agree

    Rust, Go, Python, Java, C++, Erlang and Zig. Each engine is written from the specification and the vectors, never from another engine's source, and uses only its language's standard library. Each must reproduce every vector byte for byte, so a defect in one engine shows as a difference from the other six.

    Ten lines

    Add a format without writing code

    This is the complete pack for a NATO Vector Graphics point, beside the message it describes.

    packs/nvg/pack.def, comments left out
    format   nvg
version  0.1.0
distribution public
source  "NATO Vector Graphics 1.5 XSD (NATO ACT, public)"
wire     xml
root     nvg
field   lon       point/@x        float
field   lat       point/@y        float
field   callsign  point/@label    string
field   type      point/@symbol   string
    The message
    <nvg><point x="11.2" y="48.137" label="ALPHA" symbol="app6a:SFGPUCI----D"/></nvg>
    With that file in packs/nvg/, in all seven engines
    $ goat-xf convert --from nvg --to geojson < point.xml
{"type":"Feature","geometry":{"type":"Point","coordinates":[11.2,48.137]},"properties":{"type":"app6a:SFGPUCI----D","callsign":"ALPHA"}}

    Each field line reads: the model key, the place in the message, the transform. The pack language also states binary layouts by bit range, scale factors, several message kinds chosen by values in the message, constants, defaults, value tables and repeating groups; the grammar is spec/engine-spec.md. A pack for a large message catalog is generated from the catalog's own machine-readable definition by the generators in tools/gen.

    Packaging

    Make exactly what you need

    Seven languages

    A native library in Rust, Go, Python, Java, C++, Erlang and Zig, each with no dependency beyond its standard library. For other hosts, the Rust engine is also a C library and a WebAssembly module with a JavaScript wrapper and TypeScript types.

    Runtimes

    The Rust and Go engines build to one fully static binary and to WebAssembly. The Java engine is a jar. The Python and Erlang engines ship with their runtime. docs/package-configurator.md has the table of build targets.

    Only the packs you name

    A pack loads on its own, so a deployment carries only the formats it uses.

    $ goat-xf list-formats --packs-only remote-id,cot-xml
cot-xml
remote-id

    The planner

    tools/goat-pkg plan takes the formats, the language and the runtime and prints the smallest package.

    $ tools/goat-pkg plan --formats remote-id,cot-xml --language rust --runtime wasm
engine:      engines/rust
packs:       remote-id, cot-xml   (only these)
wires used:  bits, xml   (a minimal engine build can exclude the rest)
build:       cargo build --release --lib --target wasm32-unknown-unknown

    To choose which formats a deployment needs, tools/goat-options lists every way data can get from a system that produces it to a system that needs it, from plain-text system records and the packs, with the status of each step (docs/system-records.md).

    Why open

    One definition of each format, in the open

    A correction reaches every user

    There is one definition of each format. A gap or an error in a pack is corrected in one file, and every user of that format, in every language, has the correction at the next update.

    The owner of a format can keep its pack

    A pack is a text file that mirrors the format's specification. The organization that writes the specification can maintain the pack directly, by pull request.

    Nothing about a format is inside a product

    Field positions, units and rules are readable text with a named source. The engines are Apache-2.0 and use only standard libraries.

    A new format reaches every language at once

    One pack makes a format convertible to and from every format already present, in all seven languages, in a browser and in a static binary.

    Private formats

    A format whose specification is not public stays private

    A pack for such a format is kept in a private overlay repository, which names the commit of this repository it builds with and adds its own packs; the same engines read both, and the format converts to and from every public format through the shared model. Every pack is marked distribution public or distribution controlled, and an engine started with --max-distribution public loads nothing marked controlled.

    docs/boundary.md states the rules and the checks. goat-transformers-overlay-example is a worked overlay with fictional content.

    Install

    Use it from the repository

    There is no package in a registry. Clone the repository and use the engine for your language; each one builds and tests with the command shown.

    Your code is inUseBuild and run every vector
    Rustengines/rust, the reference engine and goat-xfcargo test --release
    Goengines/gogo test ./...
    Pythonengines/pythonPYTHONPATH=src python3 -m unittest discover -s tests
    Javaengines/java./build.sh
    C++engines/cppcmake -S . -B build && cmake --build build && ctest --test-dir build
    Erlangengines/erlang./build.sh && ./run_tests
    Zig 0.13engines/zigzig build test
    JavaScript or TypeScript, in Node or a browserbindings/wasm, the module this page runsnode --test bindings/wasm/test/vectors.test.mjs
    C, or a language that can call Cbindings/ccd bindings/c && ./test.sh

    Each command runs from the directory in its row; the two bindings commands run as written from the repository root, the WebAssembly one after the module is built. bindings/README.md shows the calls of the C library and the WebAssembly module. CONTRIBUTING.md states how to add a pack, a wire type or an engine. The library is pre-1.0: the pack language and the engine interfaces can still change.
