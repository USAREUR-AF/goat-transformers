goat-transformers

Any message format to any other. Every format is a data file.

A drone's 25-byte Remote ID broadcast becomes a Cursor on Target event for a tactical map. No engine holds code for either format: each is a pack, a text file with one line for each field, and seven engines in seven languages read the same packs and must agree byte for byte.

One message, two targets

The same 25 bytes, written for a map and for a ship

Quick start: needs a Rust toolchain and nothing else
git clone https://github.com/USAREUR-AF/goat-transformers
cd goat-transformers/engines/rust && cargo build --release
echo 122624160b42bf241b6ed1b4b69808ac0870086b53150e0200 \
  | ./target/release/goat-xf convert --from remote-id --to cot-xml --packs-only remote-id,cot-xml

In: Remote ID Location message, 25 bytes (ASTM F3411)

0123456789101112131415161718192021222324 122624160b42bf241b6ed1b4b69808ac0870086b53150e0200 latlonhae

--to cot-xml  Cursor on Target event, the XML that tactical map software reads

<event version="2.0" type="a-u-X"><point lat="45.539309" lon="-122.966389" hae="110" ce="9999999" le="9999999"/><detail/></event>

--to nmea2000  parameter group 129025, the position message of a ship's instrument network, 11 bytes: 01f80142bf241b6ed1b4b6

012345678910 01f80142bf241b6ed1b4b6 latlon

lat, lon and hae (height above the ellipsoid) are keys of the shared model. 9999999 is Cursor on Target's value for "not known". Both outputs are what goat-xf, the command-line tool, prints for this input.5

    What it is

    Formats are data. Engines are generic.

    A format is a data file

    A pack is a directory with a pack.def: the format's name, its wire type, the public document it was written from, and one field line for each value. A wire type is an engine's codec for a family of encodings; there are seven: bits, geojson, json, protobuf, text, tlv and xml. Adding a format whose wire type exists changes no engine.

    One shared model

    Every pack maps its fields to typed keys in fixed units: degrees, meters, meters per second, milliseconds since 1970. A conversion decodes the source message to the model and encodes the model to the target, so 4,115 formats need 4,115 packs, not 16,929,110 converters, one for each ordered pair.

    Seven engines that must agree

    Rust, Go, Python, Java, C++, Erlang and Zig. Each engine is written from the specification and the vectors, never from another engine's source, and uses only its language's standard library. Each must reproduce every vector byte for byte, so a defect in one engine shows as a difference from the other six.

    $ goat-xf convert --from nvg --to geojson < point.xml

    Each field line reads: the model key, the place in the message, the transform. The pack language also states binary layouts by bit range, scale factors, several message kinds chosen by values in the message, constants, defaults, value tables and repeating groups; the grammar is spec/engine-spec.md. A pack for a large message catalog is generated from the catalog's own machine-readable definition by the generators in tools/gen.

    Packaging

    Make exactly what you need

    Seven languages

    A native library in Rust, Go, Python, Java, C++, Erlang and Zig, each with no dependency beyond its standard library. For other hosts, the Rust engine is also a C library and a WebAssembly module with a JavaScript wrapper and TypeScript types.

    Runtimes

    The Rust and Go engines build to one fully static binary and to WebAssembly. The Java engine is a jar. The Python and Erlang engines ship with their runtime. docs/package-configurator.md has the table of build targets.

    Only the packs you name

    A pack loads on its own, so a deployment carries only the formats it uses.

    $ goat-xf list-formats --packs-only remote-id,cot-xml
cot-xml
remote-id

    The planner

    tools/goat-pkg plan takes the formats, the language and the runtime and prints the smallest package.

    Why open

    One definition of each format, in the open

    A correction reaches every user

    There is one definition of each format. A gap or an error in a pack is corrected in one file, and every user of that format, in every language, has the correction at the next update.

    The owner of a format can keep its pack

    A pack is a text file that mirrors the format's specification. The organization that writes the specification can maintain the pack directly, by pull request.

    Nothing about a format is inside a product

    Field positions, units and rules are readable text with a named source. The engines are Apache-2.0 and use only standard libraries.

    A new format reaches every language at once

    One pack makes a format convertible to and from every format already present, in all seven languages, in a browser and in a static binary.

    Private formats

    A format whose specification is not public stays private

    A pack for such a format is kept in a private overlay repository, which names the commit of this repository it builds with and adds its own packs; the same engines read both, and the format converts to and from every public format through the shared model. Every pack is marked distribution public or distribution controlled, and an engine started with --max-distribution public loads nothing marked controlled.

    docs/boundary.md states the rules and the checks. goat-transformers-overlay-example is a worked overlay with fictional content.

    Under the hood

    The shared model

    Every format in this library converts through one common set of typed values: the shared model. This section says what it is, why the library is built on it, what it guarantees, and how it is kept safe. The full definition is spec/shared-model.md.

    What it is

    A conversion is two steps: decode the source message into keys of the model, then encode those keys into the target format. No format is converted to another directly.

    PartWhat it holdsDefined in
    corewhat any position report means, in fixed units: identifier, type, time, latitude and longitude (WGS 84), height above the ellipsoid, horizontal and vertical error, course, speed, name. These are the fields of a Cursor on Target event.model/core.def
    trackfacts about a sensor track: its source, velocity vector, class, confidence, uncertainty and status flags. These follow the Canonical Track v2 contract field for field.model/track.def
    one module per formatevery other field of that format, under its own name, so that nothing is lost when a message goes back to its own formatmodel/<module>.def

    Units are fixed by the model, not by a format: degrees, meters, meters per second, milliseconds since 1970 (UTC). Each format's pack converts its own units on the way in and on the way out.

    Why a shared model

    ApproachWork for N formatsA new format needs
    A converter for each pair of formatsN × (N − 1) convertersa converter to and from every existing format
    One shared model (this library)N packsone pack

    The same pattern carries other wide conversion tools: pandoc converts documents through one document model, and GDAL converts geographic data through one data model.

    The library does not use an existing message standard as the hub. Each candidate covers one domain (air traffic, land tactical data, maritime, space telemetry) and leaves the others out, several are heavy to implement, and some are not public. The shared model reuses existing definitions where they fit instead of inventing new ones: core is the Cursor on Target event, and track is the Canonical Track v2 contract.

    What it guarantees, and what it does not

    ConversionWhat happens
    A format to itselfNothing is lost. A field the model has no key for is kept with the message and written back, so the message returns in its canonical form. Round-trip conformance vectors pin this.
    One format to anotherExactly the values that both formats map carry. The capability report (goat-xf capability --from A --to B, or goat-xf matrix) lists what carries and what is dropped, from the two packs alone, before any message is converted.
    A pair that must lose nothingNot guaranteed by the model. A direct rule for that pair is planned (spec version 0.53).

    Cross-format loss is listed by the capability report but not yet reported per message. A per-conversion loss report, and a strict mode that refuses a conversion that would drop a field the caller requires, are being added.

    How it is kept safe

    RiskSafeguard
    A key changes meaning under its usersKeys are never renamed and never change type. A new meaning is a new key.
    A pack writes a value of the wrong typeEvery engine checks each pack against the model when it loads, and refuses a mismatch.
    One implementation reads the model differentlySeven engines, written independently from the specification, must give the same bytes on every conformance vector.
    All engines agree on a wrong valueValues are compared with the projects' own encoders and decoders on their own inputs (docs/consumer-proofs.md). Every conversion vector's decoded values are checked against a plausible range or set for their key (latitude, longitude, height, errors, course, speed, times, confidence, class, flags), and every pack that maps a height must name its vertical datum (tools/model-checks.py, rules in tools/model-ranges.json). Checks against each format's reference implementation are being added.
    A change to the model breaks a userEach project pins a library commit, so a change reaches no one until they move. A change to core or track needs a written decision record (docs/adr/) and is measured against every known user before it merges.

    Time quality

    Time quality travels with every report, on two independent axes. A pack never invents it: each key is absent unless the source message states it.

    AxisKeysStatus
    Coherence of the clock that stamped the reporttime_error_ms (the error bound), time_state (coherent, drifting or free-running)in core
    Confidence in UTC, and a signed attestation of time qualitythe UTC state, its error bound, the anchor and the age of the last anchor; an attestation referencebeing added

    A clock can be coherent while its relation to UTC is unknown. That is a normal, healthy state, and with the second axis the model can state it.
