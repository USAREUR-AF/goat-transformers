# sbas-l1

SBAS L1 messages (WAAS, EGNOS, MSAS, GAGAN, SDCM, BDSBAS and other satellite-based
augmentation systems): the message types RTKLIB decodes. Generated by
`tools/gen/sbas2pack.py`.

RTCA DO-229, which defines the messages, is a paid document and is not used. The
layouts are those RTKLIB's `src/sbas.c` (BSD-2-Clause) reads, restated in this
repository's words. gnss-sdr's SBAS decoding is RTKLIB's code, so it adds no type.

## Message convention

One message is the 250-bit message (an 8-bit preamble, the 6-bit message type,
212 data bits, the 24-bit CRC-24Q) followed by 6 zero bits: 32 bytes, as hex text,
most significant bit first. The message type selects the kind. The preamble and
the CRC are raw keys of every kind; the CRC is carried, not computed, and decode
does not check it.

| Kind | Type | Content |
|---|---|---|
| `type-1` | 1 | PRN mask: 210 one-bit items (`sbas.prn_mask`), IODP |
| `type-2` … `type-5`, `type-0` | 2-5, 0 | IODF, IODP, 13 fast corrections (0.125 m) and 13 UDREIs; type 0 (test) read as type 2, as RTKLIB reads it |
| `type-6` | 6 | four IODFs and 51 UDREIs |
| `type-7` | 7 | system latency, IODP, 51 degradation factor indicators |
| `type-9` | 9 | GEO navigation message: t0, URA, ECEF position, velocity, acceleration, clock offset and drift |
| `type-18` | 18 | number of bands, band, IODI, 201 grid point mask bits |
| `type-24` | 24 | 6 fast corrections and UDREIs, IODP, block, IODF, and one long-term correction half |
| `type-25` | 25 | two long-term correction halves |
| `type-26` | 26 | band, block, 15 grid points (vertical delay, GIVEI), IODI |

A long-term correction half (106 bits) is an item of `sbas.long_term` whose layout
its velocity code chooses: gate blocks (engine-spec 0.17) inside the item read two
satellites' position and clock corrections (code 0) or one satellite's position,
velocity, clock and time of applicability (code 1). A vertical delay of 511 (not
monitored) is absent (`absent 511`).

## Shared keys

None. Type 9 states the GEO satellite's position in earth-centred, earth-fixed
coordinates; RTKLIB does not state the frame beyond "ecef", and DO-229 is not
read, so `lat`, `lon` and `hae` are not derived from it. Times are seconds of the
GPS day without the day: `time_ms` is not stated.

## Not mapped

| What | Why |
|---|---|
| types 10, 12, 17, 27, 28 (degradation parameters, SBAS network time, GEO almanacs, service message, clock-ephemeris covariance) and 62, 63 | RTKLIB, the open source read, does not decode them; DO-229 is a paid document |
| which satellite a fast correction or grid point is for | it follows from the PRN mask (type 1) and IGP mask (type 18), other messages |
| the CRC as a check | the `bits` wire computes no CRC |

## Vectors

`tools/gen/sbas2pack.py` writes one round trip per kind, a type 26 with a grid
point not monitored, and two error cases, with its own bit writer; it packs the
fields one after another and checks that each lands at the offset RTKLIB reads.
No engine is run.
