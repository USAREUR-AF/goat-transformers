## How a schema is read

Each member of a scalar type is a `field` line; members of nested objects have dotted paths.
An array is a `group` (engine-spec 0.7): items that are objects are walked as a message is,
with paths relative to the item; items of a scalar type are one `.` line. `allOf`, `oneOf`
and `anyOf` contribute the members of every branch, merged by name; `null` among the
types means the member may be absent. Types: string `string`, integer `int`, number
`float` (`int` when the schema states `multipleOf: 1`), boolean `bool`. A `date-time`
string is kept as text in its raw key, so it round-trips as written.

Residue (engine-spec 0.5): a scalar member no line maps, at any depth of nested objects, is
carried back; arrays no group maps, and anything inside them, are not.

## The form

One message is one EVE JSON record as Suricata writes it to `eve.json`: one JSON object
per line, with `timestamp`, `event_type`, the flow's address tuple and one member object
named after the event type. The pack has one kind per event type it maps (`alert`, `flow`,
`dns`, `http`, `tls`, `fileinfo`, `anomaly`, `stats`), chosen by `event_type`. The kinds
are cut from the one EVE schema by `tools/gen/suricata-eve-schemas.py`: each holds the
top-level scalar members and its own member object (an alert also its `flow` object).
Member objects of other event types inside a record are residue (their scalars) or not
carried (their arrays).

## Shared keys

None.

- `time_ms` is not bound. Suricata writes `timestamp` as an ISO 8601 date and time with
  microseconds and an offset written without a colon (`2023-09-18T06:13:41.532140+0000`,
  the form `doc/userguide/output/eve/eve-json-format.rst` shows), and `iso8601_ms` refuses
  an offset without its colon (ruling 3a of 0.11). The text is the raw key
  `suricataeve.timestamp`.
- `uid` is not bound: `flow_id` is a number, and `community_id` names a flow, not one
  record.
- Addresses and ports are network endpoints, not positions.

## Keys and lists

Module `suricataeve`: 1335 keys, 48 lists. A key is named by its path (`a.b` is `a_b`; inside a list, the
list name comes first). Names are pinned in `tools/gen/names/suricata-eve.json`: a later run keeps every
existing name and only adds new ones.

## Vectors

One same-format round trip per kind, computed by the generator's own json codec (no engine):
every mapped place holds a value, an array has two items (one inside an item), the input is
canonical, so the expected output is the input.
