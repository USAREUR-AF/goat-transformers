## How a schema is read

Each member of a scalar type is a `field` line; members of nested objects have dotted paths.
An array is a `group` (engine-spec 0.7): items that are objects are walked as a message is,
with paths relative to the item; items of a scalar type are one `.` line. `allOf`, `oneOf`
and `anyOf` contribute the members of every branch, merged by name; `null` among the
types means the member may be absent. Types: string `string`, integer `int`, number
`float` (`int` when the schema states `multipleOf: 1`), boolean `bool`. A `date-time`
string is kept as text in its raw key, so it round-trips as written.

Residue (engine-spec 0.5): a scalar member no line maps, at any depth of nested objects, is
carried back; arrays no group maps, and anything inside them, are not.

Limits of this pack: objects nested deeper than 3 levels (an array counts as a level) are not mapped; an array inside 2 arrays is not mapped (FHIR datatypes and backbone elements nest without bound (Reference.identifier.assigner is a Reference); three levels hold a resource's elements, the members of its datatypes and of its backbone elements, and an array inside two arrays is not mapped). Such a place is in the table under Not mapped;
outside an array its scalars are residue and round-trip, inside an array they are dropped.

Members not mapped at any depth: `extension`, `modifierExtension`, `contained`, names beginning `_` (every element may carry extension and modifierExtension (arrays of Extension, whose value[x] is any datatype), every primitive a _<name> sibling holding its id and extensions, and contained holds whole resources of any type; walked, they would multiply each pack many times over, so they are not mapped and the json wire drops their arrays). They are in the table under Not mapped;
outside an array their scalars are residue and round-trip, inside an array they are dropped.

## What a message is

One FHIR R4 resource in its JSON form (https://hl7.org/fhir/R4/json.html): a JSON object
whose `resourceType` names the resource. Each resource type is its own pack with one kind,
selected by `resourceType`. A Bundle is a pack of its own (`fhir-r4-bundle`); the resources
inside its entries are not mapped there (see the limits below).

## Evidence for the shared keys

- `uid` (`id`): the logical id of the resource on its server; FHIR states it never changes
  once assigned.
- `time_ms` (`meta.lastUpdated`): when the resource last changed, a FHIR `instant` (date, time
  to the second and a time zone, optional fraction). `iso8601_ms` reads it in UTC and writes
  it with milliseconds and `Z`; the raw key keeps the text as written, and digits of the
  fraction past the third are dropped by the transform.
- Location only: `lat` and `lon` (`position.latitude`, `position.longitude`): FHIR states the
  position in the WGS 84 datum, with the value domain of KML's latitude and longitude:
  decimal degrees. `position.altitude` is not bound to `hae`: FHIR gives it the meaning of
  KML's altitude, metres measured from sea level or from the ground (KML's altitudeMode,
  which FHIR does not carry), never from the WGS 84 ellipsoid; it is a raw key.

## Choice types and extensions

- **Choice types** (`value[x]`, `effective[x]`, ...): the schema lists each choice as its own
  member (`valueQuantity`, `valueString`, ...), so each is mapped as a member like any other,
  within the depth limit. Nothing ties the alternatives together; a message holds one of
  them.
- **Extensions** (`extension`, `modifierExtension`) and the `_<name>` siblings that carry a
  primitive's id and extensions are not mapped (see the limits below): an extension's value
  is any FHIR datatype, chosen by `url`, which a `json` line cannot select.
- **`contained`** resources are not mapped: each is a whole resource of any type.
