## How a schema is read

Each member of a scalar type is a `field` line; members of nested objects have dotted paths.
An array is a `group` (engine-spec 0.7): items that are objects are walked as a message is,
with paths relative to the item; items of a scalar type are one `.` line. `allOf`, `oneOf`
and `anyOf` contribute the members of every branch, merged by name; `null` among the
types means the member may be absent. Types: string `string`, integer `int`, number
`float` (`int` when the schema states `multipleOf: 1`), boolean `bool`. A `date-time`
string is kept as text in its raw key, so it round-trips as written.

Residue (engine-spec 0.5): a scalar member no line maps, at any depth of nested objects, is
carried back; arrays no group maps, and anything inside them, are not.

## What is not carried

The temporal properties of one moving feature. The response is close to hollow: the
`temporalProperties` member is either the Prism form (objects keyed by property name, with
tuple-shaped values) or a list of temporal properties, and the generator reads that choice
as a tuple, so it is not mapped. Only the links, `timeStamp`, `numberMatched` and
`numberReturned` are. Read a single property with `ogcapi-mf-api-tproperty`. No shared key is
bound.

The schemas of the API response refer to the MF-JSON Prism schema by its schemas.opengis.net
address; the run reads that file (pinned by SHA-256 in the run script). It states no licence,
so the pack is labelled `LicenseRef-unstated` (REUSE.toml); the response schemas themselves
are under the OGC Software License.
