# Pack: dis7

Distributed Interactive Simulation, version 7 (IEEE 1278.1-2012): one kind per
PDU type. Layouts from the open-dis PDU descriptions (`https://github.com/open-dis/xmlpg`, `DIS2012.xml`, commit
`35ed3733009a89a34604abad87d1aefc1fdfbbc2`); the PDU type numbers from open-dis-python (`https://github.com/open-dis/open-dis-python`, `opendis/dis7.py`,
commit `48cb4fa59b44ad50d9f519190e53609ef7a3ef19`). Public. Generated by `tools/gen/dis2pack.py`; do not edit
`pack.def`, this file, `PROVENANCE.md`, `model/dis7.def` or the vectors by hand.

Status: Built. Generated and checked by the generator's own serializer and codec.

No IEEE document was read: the layouts are those of the open-dis project, a
BSD-licensed restatement. The xmlpg README says the XML description is no
longer maintained and that corrections go to the generated libraries; each
built kind was compared with open-dis-python's own reading of its vector (see
PROVENANCE.md).

## The message

`wire bits`, `bit_order msb`, `word_bytes 1`; hex text. One PDU from its first
byte; every number is big-endian (network byte order: open-dis-python reads
with `>` struct formats). The PDU header is 12 bytes:

| Bytes | Field | In the pack |
|---|---|---|
| 0 | protocol version | common `when` = 7 |
| 1 | exercise id | `dis7.header_exercise_id` |
| 2 | PDU type | per-kind `when` |
| 3 | protocol family | `dis7.header_protocol_family` |
| 4-7 | timestamp | `dis7.header_timestamp` |
| 8-9 | PDU length in bytes | per-kind `when` for a fixed length; `dis7.pdu_length` for a kind with a counted list |
| 10 | PDU status | `dis7.header_pdu_status` |
| 11 | padding | `dis7.header_padding` |

A kind with a counted list cannot state its length as a `when`, and the pack
does not compute it: encode writes `dis7.pdu_length` as the entity holds it, so a
PDU encoded from another format needs the length set by the caller (or a derive
of the length from the items, which the pack language does not have).

## What is mapped

| Description | Transform | Model type |
|---|---|---|
| unsigned byte, short, int, long | `uint` | int |
| byte, short, int, long | `twos` | int |
| float, double | `f32`, `f64` (big-endian) | float |
| a fixed list of bytes marked as text (an entity marking) | `ascii` | string |
| a record (`classref`) | its fields in place, the path joined by `_` | as the field |
| a fixed list | one field per element, `_01`, `_02`, … appended | as the element |
| a counted list that ends the PDU, of fixed-size items | a `group` of `item` bits counted by its count field | a list |

The count field of a counted list is the group's count locator: encode writes
the number of items there, and the field has no key of its own.

### Core keys

None. The Entity State PDU and the others that place an entity give its
location as geocentric (ECEF) coordinates in metres and its velocity in the
same frame: binding `lat`, `lon` and `hae` needs a derive from ECEF to geodetic
coordinates (WGS84), which the pack language does not have, so they stay raw
keys (`entity_state_entity_location_x`, …). The entity id is three numbers (site,
application, entity) with no single-key form in the source, so it stays raw too;
a derive that joins them would give `uid`. The marking is free text, not stated
as a call sign. The timestamp counts units of an hour, not epoch time.

### `requires`

Each kind requires up to 3 of its own keys, so an entity from another format
selects a kind only when it holds them.

## Vectors

`vectors/rt-<type>-<kind>.json`: one same-format round trip per kind, the PDU
written by a serializer in the generator from sample values; a kind with a
counted list has one with two items and one with none (`-no-items`). No
conversion vector: no field binds a core key without the ECEF derive.
