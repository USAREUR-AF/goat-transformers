# Pack: asterix-cat001

ASTERIX Category 001, Transmission of Monoradar Data Target Reports, edition 1.4 (2022-08-18): one data block holding one record.
Public. Generated by `tools/gen/asterix2pack.py` from the machine-readable definition of the
category in `github.com/zoranbosnjak/asterix-specs` (BSD-3-Clause), file `specs/cat001/cats/cat1.4/definition.json` at commit
`64e9ffba964b92a1af3157bc6bdf7852a63bf700`. The category itself is specified by EUROCONTROL. I/O is hex text.
Needs engine version 0.20 (`switch`).

Uses the modules `core` and `cat001` (`model/cat001.def`, generated with the pack).

## Layout

`layout sequential`, `bit_order msb`. One kind, `record`.

| Part | Lines | Meaning |
|---|---|---|
| CAT, one octet | `when 8 1` | selects the kind; another category is `no-kind` |
| LEN, two octets | `length 16 whole` | the block length in octets, CAT and LEN included; written on encode, and on decode input beyond it is not read |
| FSPEC | `presence f fx` | bit n is FRN n of the UAP |
| common items | one `if f.<frn>` block per FRN up to 2, I001/020 | the same items in every UAP |
| `switch cat001.i020_typ` | one `case` per UAP after the first, and `else` | the items of the UAP that I001/020/TYP selects, one `if f.<frn>` block per mapped FRN |

A data block that holds more than one record: the first record is read and the rest of the block is not.

### The UAPs

The definition gives the category 2 UAPs and names I001/020/TYP as the field whose value says which one
a record follows. Every UAP holds the same items up to FRN 2, so those are written once, before a
`switch` on `cat001.i020_typ` (engine-spec 0.20):

| UAP | Arm | I001/020/TYP | FRNs | mapped |
|---|---|---|---|---|
| `plot` | `else` | 0, or the item absent | 21 | 16 |
| `track` | `case 1` | 1 | 22 | 21 |

- **Decode.** The value read from I001/020/TYP picks the case. A record without I001/020 leaves the key absent,
  and the `else` lines are read: UAP `plot`, which is also the layout the earlier one-UAP pack read.
  The definition names no UAP for a record without the item; reading the first is this pack's choice.
- **FSPEC bits.** Only the `if` lines of the case read name FSPEC bits, so a bit that only another UAP
  maps is `malformed-wire` in a record of this UAP.
- **Encode.** The case is the one decode would pick from what was written: the value of `cat001.i020_typ`,
  zero when the item is written without it, and `else` when the item is not written at all. Keys of
  items that only another UAP holds are not written.
- **One kind.** The UAP is not a kind: `@kind` is `record` for every UAP, and the decoded `cat001.i020_typ`
  tells them apart. An item two UAPs share has one set of keys, whichever FRN it has in each.

How each item type of the definition is written:

| Item type | Lines |
|---|---|
| fixed | one `field` per subitem, `pad` for spare bits |
| extended | `chain`: the fields of a part, then `fx` for its extension bit |
| repetitive with a count octet | `group <list> count 8`, the body being one repetition |
| repetitive with an extension bit per repetition | `group <list> fx` |
| compound | `presence <name> fx` for the primary subfield, then one `if <name>.<n>` block per subfield |
| explicit (SP, RE) | `length 8 bytes plus 1` with an empty block: the length octet counts itself, so the block is the stated length less one. The content is not mapped |

How each content type is written:

| Content | Transform | Key type |
|---|---|---|
| raw bits, a table of values (enumeration), a Mode S BDS register | `uint` | int |
| integer | `uint`, or `twos` when signed | int |
| quantity with an LSB and a unit | `uscale:<LSB>`, or `sscale:<LSB>` when signed, the LSB as an exact fraction | float, in the unit of the definition |
| ASCII string | `ascii` | string |
| string of 6-bit ICAO characters, octal digits | `uint` | int: the raw bits |
| content that depends on another subitem | `uint` | int: the raw bits |

## Items not mapped

No `if` line of the case read names these FSPEC bits. A record of that UAP with one of them set fails
to decode with `malformed-wire`, and encode never sets them.

| UAP | FRN | Item | Reason |
|---|---|---|---|
| `plot` | 16 | - | spare FRN |
| `plot` | 17 | - | spare FRN |
| `plot` | 18 | - | spare FRN |
| `plot` | 19 | - | spare FRN |
| `plot` | 21 | - | random field sequencing: the items that follow name themselves by FRN, in any order |
| `track` | 21 | - | random field sequencing: the items that follow name themselves by FRN, in any order |

Mapped without content: SP, Special Purpose Field (FRN 20 in `plot` and 20 in `track`). Decode reads the length octet and passes over the content; no key holds it,
so encode never writes the item, and a same-format round trip of a record that holds one returns the
record without it.

## Shared-model keys

A shared key is bound only where the text of the definition and the unit leave no doubt, and only on an
item that stands directly in the UAP. The text quoted is the definition's.

| Shared key | Bits | How | Text of the definition |
|---|---|---|---|
| `speed_ms` | I001/200/GSP | `field speed_ms … uscale:463/4096`: factor 1852 folded into the scale; the field has no raw key | I001/200 "Calculated Track Velocity in Polar Co-ordinates", subitem GSP "Calculated Groundspeed"; LSB 1/16384 NM/s |

Where a field has a shared key and a raw key, the shared key is on the `field` line and the raw key on
the `also` line. Decode fills both. Encode writes the earliest key that is present (ruling 13 of 0.8), so
the shared key wins: a consumer that changes `lat` sees the change on the wire, and a change made only
to the raw key is not written (ruling 16 of 0.5 asks for this order).

Where the unit of the definition is not the unit of the shared key, the conversion factor is part of
the scale (one foot is 381/1250 m, one NM/s is 1852 m/s, one knot is 1852/3600 m/s), the field holds
the shared key alone, and `model/cat001.def` has no raw key for it: an `also` line shares the transform of
its field, so one field cannot hold feet in one key and metres in another.

`speed_ms` stands in I001/200, which only UAP `track` holds: it is read and written only in that case. An entity
converted from another format reaches it only when it also holds `cat001.i020_typ` with that UAP's value.

Not bound, on purpose: a position, height or speed inside a compound or repetitive item (it describes
something other than the reported target's own state, or one of several); a flight level or barometric
altitude (`hae` is geometric); a heading, or a track angle whose reference the definition does not state
(`course` is degrees true); a Cartesian velocity or position in a local system whose axes the definition
does not state; a polar position relative to a sensor; a time item where the category has several.

## Converting to this pack

The kind has no `requires` line: the definition does not mark items as mandatory, so encode writes the
items whose keys the entity holds. A field of a written item whose key is absent is written as zero.
The UAP follows `cat001.i020_typ` as written (section "The UAPs"): an entity without it is written with UAP
`plot`, and keys of items only another UAP holds are left out.
Keys of `cat001` that another format does not carry (SAC and SIC, for example) are given as context.
