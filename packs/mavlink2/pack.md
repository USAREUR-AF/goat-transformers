# Pack: mavlink2

MAVLink 2 frames carrying the `common.xml` message set (with the files it
includes, `standard.xml` and `minimal.xml`). Public. Generated by
`tools/gen/mavlink2pack.py` from `https://github.com/mavlink/mavlink` at commit `12c898d88ce18d24e8caf6338596e98c5005bc97`;
do not edit `pack.def`, `model/mavlink.def`, this file or the vectors by hand.
I/O is hex text (`spec/engine-spec.md`, bits wire).

Status: Built. Generated and checked by the generator's own reader; every engine
runs every vector in `vectors/` in the conformance suite.

## Layout

`wire bits`, `bit_order lsb`, `word_bytes 1`. A locator is `0:<bit offset>:<len>`
counted from the first bit of the STX byte.

| Part | Bytes | Locator | In the pack |
|---|---|---|---|
| STX | 1 | `0:0:8` | common `when` = 253 (0xFD) |
| LEN | 1 | `0:8:8` | per-kind `when` = full payload length |
| INCOMPAT | 1 | `0:16:8` | `mavlink.incompat_flags` |
| COMPAT | 1 | `0:24:8` | `mavlink.compat_flags` |
| SEQ | 1 | `0:32:8` | `mavlink.seq` |
| SYSID | 1 | `0:40:8` | `mavlink.sysid` |
| COMPID | 1 | `0:48:8` | `mavlink.compid` |
| MSGID | 3, little-endian | `0:56:24` | per-kind `when` = message id |
| PAYLOAD | LEN | from `0:80` | the kind's `field` lines |
| CRC | 2 | after the payload | not mapped |

One `kind` per message, named by the message name in lower case, in message-id
order. Payload fields sit at their MAVLink 2 wire offsets: base fields in
descending type-size order (stable), then extension fields in declaration order.
The generator confirms its field order by computing each message's CRC_EXTRA and
comparing six of them with the values the protocol fixes.

### Key names

A key is `mavlink.<field name>` with the unit appended when the field declares
one and the name does not already end with it (`mavlink.alt_mm`,
`mavlink.time_boot_ms`). Unit text is lower-cased; `/` becomes `_per_`, `%`
becomes `pct`, `*` becomes `_x`. One key is shared by every message whose field
has that name with the same type class (int, float, string), units and enum.
When the uses of a name disagree, every use takes the message name as a prefix
(`mavlink.<message>_<field>…`). 154 fields are named that way:

| Reason | Fields |
|---|---|
| different enums | 78 |
| different types | 65 |
| same name as a frame-header key | 11 |

### Core keys

18 kinds map core `lat` and `lon`: `gps_raw_int`, `global_position_int`, `global_position_int_cov`, `hil_state`, `hil_gps`, `hil_state_quaternion`, `gps2_raw`, `terrain_request`, `terrain_data`, `terrain_report`, `follow_target`, `gps_input`, `adsb_vehicle`, `camera_image_captured`, `camera_tracking_geo_status`, `global_position_sensor`, `ais_vessel`, `utm_global_position`.
The position is the one the message reports, which is not always the sending
vehicle's: `terrain_request`, `terrain_data` and `terrain_report`
carry a terrain grid point, `follow_target` a target, `camera_image_captured` the
camera at capture time.

`gps_raw_int`, `hil_gps`, `gps2_raw`, `gps_input` carry `fix_type`, where 0 and 1 are no fix (enum `GPS_FIX_TYPE`:
`GPS_FIX_TYPE_NO_GPS`, `GPS_FIX_TYPE_NO_FIX`; the `HIL_GPS` field text: 0-1 no fix).
Their `lat` and `lon` lie in a gate block `if !<fix_type> 0,1` (engine-spec 0.17),
so a message without a fix gives no position; the same bits are the raw keys
`mavlink.lat_dege7` and `mavlink.lon_dege7` outside the block, and the frame comes back byte
for byte. Encoded from `lat` and `lon` with no raw key of the message's `fix_type`,
the gate writes 2 (2D fix), the smallest value that is a fix; with a raw `fix_type` of
0 or 1 an entity that holds `lat` or `lon` without the raw keys is `transform-encode`.
`terrain_check` has no field but `lat` and `lon`; they stay raw there so the kind has a raw
key to require, otherwise any entity with a position would encode as that kind.

Left raw on purpose:

- degE7 fields that are not named `lat` / `lon` (30 fields, for example `latitude`
  and `lat_int`). The `lat` / `lon` of `adsb_vehicle`, `ais_vessel` and
  `global_position_sensor` declare INT32_MAX for unknown; the pack states that as
  `absent` (Values that mean unknown, below), so they bind core `lat` / `lon`.
- Times the definition gives as "UNIX epoch time or time since system boot"
  (most `time_usec` fields), times since boot, a date of manufacture and a count
  of GPS seconds: only a time stated as since the Unix epoch is `time_ms`
  (Times, below).
- Altitude. MAVLink `alt` fields are above mean sea level; core `hae` is above
  the WGS84 ellipsoid.
- Speed, course, heading and velocity components (`vel`, `cog`, `hdg`, `vx`…):
  the reference frame is in the description text, not in the units.

### `requires`

Each kind requires up to 6 of its own raw keys, the ones used by the fewest
kinds, so encoding an entity that came from another format selects a kind only
when the entity holds those `mavlink.` keys. No kind requires a core key, so a
GeoJSON or CoT entity selects no kind (`no-kind`).
For 45 kinds the required keys are all mapped by at least one other kind.
Encode selects the first kind whose required keys are present, so pack.def
writes a kind before every kind whose required keys it maps, unless that kind
also maps all of its own; otherwise the kinds are in id order. An entity built
from a kind's keys, with its kind cleared, therefore selects that kind.
The exceptions, where two kinds each map the other's required keys: `mission_write_partial_list` selects `mission_request_partial_list`, `mission_clear_all` selects `mission_request_list`, `safety_allowed_area` selects `safety_set_allowed_area`, `vision_position_estimate` selects `global_vision_position_estimate`, `hil_optical_flow` selects `optical_flow_rad`, `scaled_imu2` selects `scaled_imu`, `log_erase` selects `param_request_list`, `log_request_end` selects `param_request_list`, `gps2_rtk` selects `gps_rtk`, `scaled_imu3` selects `scaled_imu`, `scaled_pressure2` selects `scaled_pressure`, `actuator_control_target` selects `set_actuator_control_target`, `scaled_pressure3` selects `scaled_pressure`, `set_home_position` selects `home_position`, `param_ext_request_read` selects `param_request_read`, `param_ext_request_list` selects `param_request_list`.

## Times

A field is bound to core `time_ms` (epoch milliseconds UTC) when its definition
states a time since the Unix epoch, or since a fixed UTC instant, and nothing
else; the transform is an integer scale of engine-spec 0.15:

| Kind | Field | Transform | The definition states |
|---|---|---|---|
| `system_time` | `time_unix_usec` | `uiscale:1/1000` | microseconds since the Unix epoch |
| `camera_image_captured` | `time_utc` | `uiscale:1/1000` | microseconds since the Unix epoch, UTC; 0 means unknown |
| `utm_global_position` | `time` | `uiscale:1/1000` | microseconds since the Unix epoch at which the position applies |
| `open_drone_id_system` | `timestamp` | `uiscale:1000:1546300800000` | seconds since 2019-01-01 00:00:00 UTC, which is 1546300800 s after the Unix epoch |
| `open_drone_id_system_update` | `timestamp` | `uiscale:1000:1546300800000` | seconds since 2019-01-01 00:00:00 UTC, which is 1546300800 s after the Unix epoch |

A microsecond count keeps whole milliseconds: decode rounds to the nearest
millisecond (half away from zero) and encode writes that millisecond times 1000,
so a frame whose count is not a whole number of milliseconds re-encodes rounded
(`vectors/tm-*.json`). The raw keys these fields had stay declared in the module.

## Values that mean unknown

A field whose definition declares an `invalid` value carries the option
`absent <raw value>[,...]` (engine-spec 0.9): the value decodes to no key, and
an entity without the key encodes the first raw value. 851 `field` lines of 394
fields carry it. The raw value is the field's bits as an unsigned integer:

| `invalid` | Raw value |
|---|---|
| `INT32_MAX`, `UINT16_MAX` and the other limits | the limit's bits (INT32_MAX: 2147483647) |
| a decimal number (`0`, `-1`, `-1000`) | its two's-complement bits for an integer, its IEEE bits for a float |
| a limit or a hex number on a float (`UINT16_MAX`, `0xFFFF`) | the IEEE bits of that number (65535.0) |
| `NaN` on a `float` / `double` | 2143289344,4290772992 / 9221120237041090560,18444492273895866368 (the quiet NaN, then with the sign bit) |
| `[v]` on an array | `v` on every element |
| `[v1,,v3,]` | `v1` on the first element, `v3` on the third |
| `[NaN:]` on a float array | NaN on every element |

`[NaN:]` means the whole array is unknown when the first element is NaN; the pack
states only that each NaN element has no value (a NaN is never a model value).
410 lines take two raw values (the NaNs); an input with the second re-encodes
with the first.

## What is not mapped

- CRC (2 bytes after the payload) and the 13-byte signature of a signed frame.
  A field line with the `optional` option could read them, but encode writes
  every field line of the kind whether its key is present or not (vector
  `06-optional-truncated-roundtrip-writes-whole-message` of
  `conformance-rules-bits`), so every unsigned frame would gain 13 zero bytes
  and every frame from another format a CRC of zero. Mapping them needs a rule
  that computes the checksum and one that writes a part only when a flag is set.

## Known limits

- **Truncated payloads.** MAVLink 2 senders drop trailing zero bytes of the
  payload and set LEN to the shorter length. Each kind matches only LEN = the
  full length, so a truncated frame decodes as `no-kind`. Reading one needs the
  future framed-binary wire (a length-prefixed payload that is zero-extended).
- **CRC.** Decode does not verify the checksum and encode does not write it.
  Encode output is the header and payload up to the last mapped byte; it is not
  a transmittable frame until a framer adds truncation and the CRC (with the
  message's CRC_EXTRA). Input that carries the CRC or a signature decodes: bytes
  after the last mapped bit are ignored.
- **Output length.** Every payload byte is mapped, so encode output is the
  `10 + LEN` bytes of header and payload, without the CRC.
- **Values that mean unknown** are stated as `absent` where the pack can
  state them (below); another NaN bit pattern than the two listed still fails
  to decode (`transform-decode`), as any NaN did before.
- **Text.** `ascii` refuses bytes outside 0x20..0x7E, so a `char[n]` field that
  holds UTF-8 or binary data fails to decode. Trailing NULs are dropped; an
  all-NUL field is the empty string, present.
- **`uint64_t`** is mapped with `uint` to the model type int; a value of 2^63 or
  above is the negative model integer with the same bits (engine-spec 0.5, ruling 2).
- **Enums and bitmasks** are carried as their integer.

## Vectors

`vectors/rt-<id>-<kind>.json`: one same-format round trip per kind. The input
is the frame as the encoder writes it (no CRC), so input and expected output
are identical. Values are inside each field's range; floats are multiples of
0.25 or 0.125; every other `uint64_t` sample has its top bit set; every other
frame has COMPAT = 1, and INCOMPAT is 0.

`vectors/x-NN-<kind>-to-geojson.json`: 10 full frames with a correct CRC,
converted to GeoJSON. Expected output: `coordinates` = `[lon, lat]` in degrees
(wire value / 10^7), `properties` empty because `geojson` carries no other key
this pack maps.
