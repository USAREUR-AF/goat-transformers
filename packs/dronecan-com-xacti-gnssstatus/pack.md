## The message

`wire bits`, `layout sequential`, `bit_order msb`. The input is the transfer
payload as the receiver reassembles it: for a single-frame transfer the frame
data without its tail byte, for a multi-frame transfer the data of all frames
without the tail bytes and without the transfer CRC. Hex text.

**Which type a payload is.** The data type ID (20305) travels in the 29-bit CAN
identifier, not in the payload, and
the payload has no field that tells the types apart. So each data type is its
own format, and the caller names the format: a receiver that reads data type
ID 20305 from a CAN identifier converts from `dronecan-com-xacti-gnssstatus`.

a little-endian field read most significant bit first, which `swap` states. The
field need not start on a byte boundary; `swap` reverses the bytes of the field's
own bits.

## What is not mapped

Every field is mapped.

- Constants of the definition (they are not on the wire).
- The transfer layer: CAN identifier, tail byte, toggle bit, transfer CRC.
- Cast modes (`saturated`, `truncated`): encode writes the low bits of a value.
