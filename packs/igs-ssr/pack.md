# igs-ssr

The IGS State Space Representation format, version 1.00 (International GNSS
Service, 2020-10-05): orbit, clock, bias and accuracy corrections for real-time
precise positioning, sent as sub-types of the proprietary RTCM 3 message 4076.
Generated by `tools/gen/igsssr2pack.py`.

**Licence: LicenseRef-unstated.** The IGS document states no licence or terms of
use; the layouts are restated in this repository's words.

## Message convention

One message is the body of one RTCM 3 frame: after the 3-octet frame header,
before the CRC-24Q, most significant bit first, read in sequence (engine-spec
0.8, 0.21). The pack checks the RTCM message number 4076 (a common `when`) and
reads the 3-bit IGS SSR version; the 8-bit IGS message number selects the kind.
This is the form the `rtcm3` pack could not state: its kinds are chosen by the
message number, and the IGS sub-type follows the version.

| Kind | IGS message numbers | Content |
|---|---|---|
| `<gnss>-orbit` | 21, 41, 61, 81, 101, 121 | header, CRS indicator, satellites: IOD, radial, along-track, cross-track corrections and their rates |
| `<gnss>-clock` | 22, 42, 62, 82, 102, 122 | satellites: clock polynomial C0, C1, C2 |
| `<gnss>-orbit-clock` | 23, … | both |
| `<gnss>-hr-clock` | 24, … | satellites: high rate clock correction |
| `<gnss>-code-bias` | 25, … | satellites, each with its code biases (a nested counted list) |
| `<gnss>-phase-bias` | 26, … | consistency indicators; satellites, each with yaw angle, yaw rate and phase biases; the bias count comes before the yaw fields (a 0.21 `count`) |
| `<gnss>-ura` | 27, … | satellites: SSR URA |
| `vtec` | 201 | the header only (below) |

`<gnss>` is `gps`, `glonass`, `galileo`, `qzss`, `bds` and `sbas`: 42 kinds and
`vtec`. Every correction is read in metres, metres per second or m/s^2 with the
exact resolution the document states (for example 0.1 mm as `sscale:1/10000`);
yaw angle and rate are read in degrees (1/256 semicircle is 45/64 degree).

## Shared keys

None. The corrections apply to the broadcast ephemeris of each satellite; the
message carries no position or time of an entity.

## Not mapped

| What | Why |
|---|---|
| `time_ms` | the epoch is seconds of the GPS week (of the day for GLONASS); the week is not in the message |
| the VTEC layers (message 201) | each layer's number of cosine and sine coefficients is computed from its degree and order ((N+1)(N+2)/2 − (N−M)(N−M+1)/2, and that minus N+1): a count computed from two fields is not a construct of the pack language. The header is read; the layers are not read and not written |
| sub-types 28 to 40 and the other reserved ranges | reserved; `no-kind` |

## A note on the document and on pyrtcm

The document's orbit message table (Table 9) names the third and fourth fields of
the satellite part IDF016 and IDF015, while its combined orbit and clock table
(Table 13) and its data field table give cross-track (IDF015, 20 bits) third and
radial rate (IDF016, 21 bits) fourth. The bit widths in Table 9 (20 then 21) agree
with Table 13; this pack follows them. pyrtcm v1.2.1 (`rtcmtypes_get_igs.py`,
IGM01) follows the field names of Table 9 and so reads 21 bits then 20 for those
two fields of the orbit message.

## Vectors

`tools/gen/igsssr2pack.py` writes one round trip per kind (two satellites, and one
and two biases where the message has biases), the VTEC header with one layer
after it (not written back), and two `no-kind` cases, with its own bit writer
from values it chooses. It checks every table total of the document against the
sum of its widths. No engine is run.
