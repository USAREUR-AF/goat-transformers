## How a schema is read

Each member of a scalar type is a `field` line; members of nested objects have dotted paths.
An array is a `group` (engine-spec 0.7): items that are objects are walked as a message is,
with paths relative to the item; items of a scalar type are one `.` line. `allOf`, `oneOf`
and `anyOf` contribute the members of every branch, merged by name; `null` among the
types means the member may be absent. Types: string `string`, integer `int`, number
`float` (`int` when the schema states `multipleOf: 1`), boolean `bool`. A `date-time`
string is kept as text in its raw key, so it round-trips as written.

Residue (engine-spec 0.5): a scalar member no line maps, at any depth of nested objects, is
carried back; arrays no group maps, and anything inside them, are not.

## Evidence for the shared keys

- `time_ms` (`feed_info.update_date`): "The UTC date and time when the GeoJSON file (representing the instance of the feed) was generated".


The road events or field devices of the feed are the group `features`; their members are
raw keys of the item, and their geometry (a LineString or MultiPoint for a road event, a
Point for a device) is a coordinate array that the json wire does not map
(several JSON types). The feature form with a Point geometry, for a device, is the pack
`wzdx-device` (4.2) and `wzdx-device-4.1`, `wzdx-device-4.0`.

The road restriction feed is the work zone feed's structure with every event of type
`restriction` (the schema requires `core_details.event_type` to be `restriction` in each
feature); the json wire has no `when` inside a list item, so the pack does not check it.
