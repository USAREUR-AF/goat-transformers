# px4-ulog-dataman-response

PX4 uORB topic `dataman_response`, message `DatamanResponse`, as the data of a ULog 'D' (logged data) message.
Generated by `tools/gen/uorb2pack.py` (run by `tools/gen/uorb2pack-run.sh`); do not
edit by hand.

## Message convention

A message of this format is the `data` of one ULog 'D' message: the bytes after
its two-byte `msg_id`, 72 bytes. ULog gives a topic its `msg_id` in an 'A'
(subscription) message of the same log, so the id has no meaning outside that log
and the data holds nothing that names the topic. There is no value on the wire a
`when` line could select by, so each topic is a format of its own and the caller
names it. Other topics with this layout: none.

The data is the C struct PX4's uORB generator writes for the message: fields
ordered by element size (8, 4, 2, 1 bytes, then nested messages; ties keep the
order of the .msg file), a nested message starting at a multiple of 8 bytes,
every nested message padded to a multiple of 8, little-endian, no gap
otherwise. The padding after the last field is not part of the data (the ULog
format lets a writer leave it out); input that has it is accepted and the
encoder does not write it. `tools/gen/uorb2pack.py` states the rule in full.

This is a different format from `ros2-px4-msgs`, which is the rosbridge JSON of
the ROS 2 copy of the same messages.

Padding bytes are not in the table: no line maps them. A numeric array of up
to 64 elements is one key per element (`_0`, `_1`, ...); a longer one is a `group`
with a fixed count. A `char` array is `ascii` text.

## Shared-model keys

None. No field of this message is stated as a WGS 84 latitude or longitude in
degrees. `timestamp` is microseconds since the system started, not UTC, so it is
not `time_ms`. Every field is a raw key of module `px4ulog`.

## Not mapped, and why

| What | Why |
|---|---|
| Padding bytes | they carry no value. On encode they are zero, so a round trip of input whose padding is not zero gives zeros there; the `bits` wire keeps no residue |
| Constants of the .msg (6) | the pack language names no constant of a field; the value is carried as a number |
| Bytes of a `char` array after its first NUL | `ascii` removes trailing NULs and refuses other bytes outside 0x20-0x7E (`transform-decode`), so text followed by leftover bytes does not decode |
| NaN and infinite floats | the `f32` and `f64` transforms refuse them on decode (`transform-decode`); PX4 writes NaN for a value it does not know |
| `uint64` values above 2^63-1 | a model `int` is a signed 64-bit integer; such a value decodes to a negative integer with the same bits and encodes back unchanged (engine-spec 0.5 ruling 2) |
| The 'A' subscription, `multi_id` and the ULog header | other messages of the log; this format is the data of one 'D' message |

## Vectors

`vectors/gen-rt.json` is a round trip with every field set: values chosen by the
generator, serialized by its own code from the layout, zero padding. `gen-*` files
beside it, where there are any, are edge and error cases and conversions to
geojson; each states its rule in `source`. 1 vector file(s).
