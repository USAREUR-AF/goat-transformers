# nga-msi-wpi

NGA Maritime Safety Information, World Port Index: one record of the response of `/api/publications/world-port-index`. Public. Generated by `tools/gen/nga-msi2pack.py` through `tools/gen/nga-msi-run.sh`; module `ngawpi` (`model/ngawpi.def`). Licence LicenseRef-NGA-MSI (PROVENANCE.md).

## Message convention

The endpoint answers one JSON object whose member `ports` is an array of records. A message of this pack is one element of that array: one JSON object, wire `json`. The caller takes the records out of the array; the envelope is not a message.

## Source

No API description was available: `https://msi.nga.mil/api` answered 503 on 2026-11-20 and no OpenAPI document of it is archived. The pack is built from 3 archived response(s) of the endpoint, 12 record(s) in all (PROVENANCE.md lists them with their SHA-256). A member's type is the JSON type its non-null values have in those records.

## Shared-model keys

None bound. The responses name their members and show their JSON types but state no meaning, unit, datum or time base, and AGENTS.md binds a shared key only on a statement of the same meaning and unit. In particular:

- `latitude` and `longitude` are degrees-minutes text; `ycoord` and `xcoord` are numbers that agree with them in every archived record (to within one minute of arc), but no datum is stated, so they are raw keys (`ngawpi.ycoord`, `ngawpi.xcoord`).

Binding `lat`/`lon` from numeric members needs a statement of their datum, which no archived response or page read gives.

## Not mapped

- Members null in every archived record show no type: `maxVesselLength`, `maxVesselBeam`, `maxVesselDraft`, `ptAvailable`, `ptLocalAssist`, `s57Enc`, `entranceWidth`, `lngTerminalDepth`, `offMaxVesselLength`, `offMaxVesselBeam`, `offMaxVesselDraft`. A non-null value of one is residue: carried back into this format, not to another.
- The response envelope and the query parameters of the endpoint.
- Types: a member whose real type differs from the archived one (an integer where the archive shows text) fails with `transform-decode`. The packs are as complete as the archived responses; an OpenAPI document of the API, when it is reachable, should replace this survey.
- Member values are carried as written: codes (`Y`, `N`, `U`, area letters) are not expanded.
