## The message

One ExtensionObject in the binary encoding, as a Variant or an ExtensionObject field carries it:
the TypeId (the NodeId of the DataType's Default Binary encoding object, in the smallest NodeId
form that holds it), the encoding byte 1 (a binary body), the Int32 length of the body, and the
body. The TypeId selects the kind; a TypeId in a larger NodeId form than the smallest does not
select a kind. A structure without that header (a field of a DataSet message, an element of a
typed array) is not a message of this pack: it has no type identifier, so nothing in the bytes
names its kind, and the language has no way for a caller to name one in a pack of several kinds.

A namespace other than 0 has no fixed index: the server's namespace table gives it one. The
four-byte NodeId form is required, and the index the message holds is the key
`opcuaautoid.namespace_index`; an entity without it encodes index 0.

## Layout

Little-endian, as `bit_order lsb` reads a byte-aligned field. String, ByteString and XmlElement
are lists of bytes counted by their Int32 length (a list of byte values, not text: the `bits`
wire has no text of a stated length). Arrays are lists counted by their Int32 length. Optional
fields are `if` blocks under the 32-bit EncodingMask read as `presence`; a union is its 32-bit
SwitchField and a `switch` on it; NodeId and ExpandedNodeId are their encoding byte and a
`switch` on it; LocalizedText is its mask read as `presence`. DateTime is a raw 64-bit integer
of 100 ns ticks since 1601-01-01 UTC unless the notes bind it.

## Not mapped

- A null String, ByteString, XmlElement or array (length -1): `count` and `length` read their
  field as unsigned, so -1 is a count larger than the message and the decode is
  `malformed-wire`. An empty one (length 0) is carried. Missing: a signed count or length whose
  value -1 means absent.
- An optional field or LocalizedText part that is present and empty (length 0): its presence bit
  is not set on encode (engine-spec 0.8, ruling 5), so it comes back absent.
- Text: the bytes of a String are carried, not the text. Missing: a transform that reads a
  length-prefixed UTF-8 string.

## Shared key: time_ms

OPC UA's DateTime is a signed 64-bit count of 100 ns intervals since 1601-01-01 00:00 UTC
(OPC 10000-6, 5.2.2.5). The value 0 stands for any time at or before that epoch and the largest
Int64 for any time from the end of the year 9999; a decoder reads both as the extremes of its
platform, which are not valid times. Core `time_ms` is milliseconds since
1970-01-01 UTC. The two epochs are 11,644,473,600,000 ms apart, so the transform
`siscale:1/10000:-11644473600000` states the conversion exactly, to the millisecond (a tick count
that is not a whole millisecond rounds), and `absent 0,9223372036854775807` reads both extremes as no time.

The binding is made for the field `Timestamp` at the top of a kind, which the AutoID NodeSet
describes as the time the result, sighting or coordinate was made:

| Kind | Field | Evidence (the NodeSet's description, in this repository's words) |
|---|---|---|
| scan results (`ocr_scan_result`, `optical_scan_result`, `optical_verifier_scan_result`, `rfid_scan_result`, `rtls_location_result`) | `Timestamp`, inherited from ScanResult | the time the scan result was created |
| `access_result`, `rfid_access_result` | `Timestamp` (optional) | the time the identifier was accessed |
| `rfid_sighting` | `Timestamp` | the time of the sighting, as a UtcTime |
| `local_coordinate`, `wgs84_coordinate` | `Timestamp` | the time the coordinate applies to (named Timestamp, typed UtcTime) |

Other DateTime fields (a decoding time, a receive time, timestamps inside nested structures)
stay raw 100 ns tick counts.

## Positions stay raw

`WGS84Coordinate` gives the latitude and longitude as doubles beside separate hemisphere strings,
so the sign of the double is not stated to carry the hemisphere; `DhcpGeoConfCoordinate` splits
each into an integer and a fraction with a resolution field; `LocalCoordinate` is in a local
frame. None is bound to core `lat` or `lon`. Binding the WGS 84 pair needs the hemisphere strings
read as text (the pack has their bytes, not their text) and a derive that signs the value.
