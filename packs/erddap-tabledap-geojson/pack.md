## How a schema is read

The message is one GeoJSON Feature. The wire addresses the Point coordinates, top-level
members and one level of `properties`; so scalar members there are `field` lines and
everything else (nested objects, arrays, booleans) is residue, which the geojson wire
carries back as it was (engine-spec 0.1, ruling 13 of 0.6).

## Mapped to shared keys

| Kind | Path | Key | Schema type | Evidence (in this project's words; the notes name the source) |
|---|---|---|---|---|
| `feature` | `geometry.lon` | `lon` | Point coordinate | see the notes below |
| `feature` | `geometry.lat` | `lat` | Point coordinate | see the notes below |
| `feature` | `properties.time` | `time_ms` (int, ms) | string, date-time | the row's time, which ERDDAP writes as an ISO 8601 date-time in UTC (its time variable, propertyUnits UTC) |

Each bound path also has its raw key on a second line (ruling 16 of 0.5): the shared
key first, so encode writes the shared value when the entity has it.

## Evidence for the shared keys

- `lon`, `lat` (`geometry` of type Point): ERDDAP writes the row's longitude and latitude as
  a GeoJSON Point; GeoJSON (IETF RFC 7946, section 4) makes them WGS 84 decimal degrees.
  ERDDAP's own variables name no datum: the binding rests on the GeoJSON form.
- `time_ms` (`properties.time`): the row's time, written as an ISO 8601 date-time in UTC (the
  collection's `propertyUnits` give `UTC`); `iso8601_ms` reads it.

## What is not carried

The other properties of a row are the dataset's own variables; they are residue, carried
back as they were. The collection's `propertyNames`, `propertyUnits` and `bbox` belong to the
collection, not to one Feature. ERDDAP has no altitude in the geometry: `altitude` or `depth`,
when the dataset has them, are properties.

## Vectors

One same-format round trip per kind, computed by the generator's own json codec (no engine):
every mapped place holds a value, an array has two items (one inside an item), the input is
canonical, so the expected output is the input.

`packs/geojson/vectors/gen-geojson-to-erddap-tabledap-geojson.json`: from the input of an existing hand-written `geojson` vector. Carried: `time_ms`, `lat`, `lon`. Not carried: `uid`, `type`, `how`, `hae`, `ce`, `le`, `callsign`.
