## Repeated fields

A `repeated` field is a `group` block and a list of module `arsdkprotosleepmode` (engine-spec 0.7). The block's
path is the field-number path of the repeated field from the scope the block stands in: the
message for a block of a kind, one item for a block inside another block. Paths of the lines
inside a block start at the item.

- A repeated message: each occurrence is an item. Its fields are the block's `field` lines, a
  repeated field inside it is a nested block. An item has no residue: a field of the item
  that no line maps is dropped on decode, so only an item whose every field is mapped comes back
  byte for byte.
- A repeated string, number, bool or enum: a block with one line, `field <key> . <transform>`.
  With `pvarint`, `psint`, `pdouble` and `pfloat` decode accepts one occurrence per value and the
  packed form, and encode writes the packed form; `pstring` is one occurrence per item. A message
  that arrives unpacked therefore leaves packed: the same values, other bytes.
- A list is named as a field at its place would be. A list inside an item, and every key of an
  item, is named from the item's message type and the path inside the item, so every list of
  one message type holds the same keys; where that name is the key the same schema field
  has outside any group, the item uses that key. Names are pinned in the names file under
  `<path>[]`, `<message>:<path in the item>` and `<message>:<field>[]item`.
- No key of an item is bound to a `core` or `track` key.
- `requires` of a kind whose only content is repeated names a list of the kind: it holds when
  the list has at least one item.

## What the message is

Parrot's newer drone features are defined in protobuf rather than in the ARSDK
XML of the `arsdk-*` packs. Each feature's schema file has an `Event` message
whose `oneof` holds every event the drone sends for that feature, and a
`Command` message for what the controller sends. The pack's message is one
serialized `Event` of the feature named above. On the ARSDK link that payload
travels inside the generic custom event of the XML feature `generic` (a service
id, a message number and the payload as binary); that framing is the `arsdk-*`
packs' concern, not this pack's.

Each member of the `oneof` is a kind of the pack, except where the run makes the
envelope one layout (below). The `Command` messages are not built here.

The schema files were read for names, field numbers and types only
(`--no-comments`); these notes are this repository's own words. The custom
options of the schemas (documentation strings, the firmware versions that
support a message, the event a command triggers) do not change the bytes on the
wire and are not carried; the file that declares them is not public, and the run
gives the generator an empty stand-in for it.

## Raw by default

No field is bound to a shared key. The positions in these schemas (the backup
link's telemetry, a geofence centre, a point-and-fly target, a navigation
location) give degrees and metres but no datum and no height reference, and a
reserved value such as 500 for an unknown latitude has no transform on this
wire, so every field is a raw key of the pack's own module and the packs convert
to no other format.

- Wrapper types (`google.protobuf.FloatValue` and the like) are carried as their
  one inner field, one level deeper in the path.
- `map` fields, `fixed32`, `fixed64` and `bytes` fields have no form on this
  wire and are not carried.
- A member that is an empty message (`google.protobuf.Empty`) holds no value and
  has no line: its presence is not carried.

## What this pack does not express

- `map` fields: no line addresses an entry by its key.
- `bytes` and the fixed-width integer types, single or repeated: no transform yields them.
- A value below path depth 6, and a message type that contains itself: the walk stops where a
  message type would stand inside itself, through a repeated field as through a single one.
