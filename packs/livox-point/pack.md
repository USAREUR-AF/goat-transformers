# livox-point

Livox SDK2 point cloud and IMU data packet. Generated by `tools/gen/cstruct2pack.py` from
`tools/gen/cstruct/livox.json` (run by `tools/gen/livox-run.sh`); do not edit by hand.

## Message convention

A message of this format is the UDP payload of one Livox SDK2 point cloud or IMU data packet:
the header struct `LivoxLidarEthernetPacket` of `include/livox_lidar_def.h` without its
flexible last member, then `dot_num` items of the struct that `data_type` names. The UDP
datagram, its ports and the device discovery are the transport's, not this pack's.

The header is `LivoxLidarEthernetPacket` up to its last member `data` (36 bytes), little-endian; `#pragma pack(1)`
is in force where it is declared, so the members follow one another with no padding.
`data_type` (byte 10) selects the kind; `dot_num` (bytes 5-6) counts the items, which follow
the header back to back. On encode the count is the number of items in the list.

## Kinds

| Kind | `data_type` | Constant | Item struct | Item bytes |
|---|---|---|---|---|
| `imu` | 0 | `kLivoxLidarImuData` | `LivoxLidarImuRawPoint` | 24 |
| `cartesian_high` | 1 | `kLivoxLidarCartesianCoordinateHighData` | `LivoxLidarCartesianHighRawPoint` | 14 |
| `cartesian_low` | 2 | `kLivoxLidarCartesianCoordinateLowData` | `LivoxLidarCartesianLowRawPoint` | 8 |
| `spherical` | 3 | `kLivoxLidarSphericalCoordinateData` | `LivoxLidarSpherPoint` | 10 |

Which struct each `data_type` carries: the header's enum `LivoxLidarPointDataType` names the
values, and the SDK's quick-start sample casts the packet's `data` to
`LivoxLidarCartesianHighRawPoint`, `LivoxLidarCartesianLowRawPoint` and `LivoxLidarSpherPoint`
for the values 1, 2 and 3 and reads `dot_num` of them. For 0 (IMU) the sample has no cast;
the pack takes `LivoxLidarImuRawPoint`, the header's only IMU sample struct, by its name.

Byte order: the header does not state it. The SDK reads a received packet by casting its
bytes onto the packed struct with no byte swap, so the wire order is the host's of the
machines it runs on; Livox's public protocol page for the Mid-360 states that the protocol
data is little-endian. Only that fact is taken from the page, which states no licence.

## Shared-model keys

None. The Cartesian points are in millimetres (high) or centimetres (low) in the LiDAR's own
frame and the spherical points are range and angles from it: no shared key has that
meaning. The packet's timestamp is 8 bytes whose epoch depends on `time_type`; the header
declares it as bytes, so it is 8 raw keys. Every field is a raw key of module `livox`.

## Not mapped, and why

| What | Why |
|---|---|
| `length` (the UDP payload length in bytes) | a raw key, written on encode as the entity holds it: a field that counts the whole message is not in the fixed `bits` layout (`length … whole` is sequential only, and this packet's count field is not adjacent to its items) |
| `crc32` | a raw key, not checked on decode and not computed on encode: the pack language has no CRC |
| `timestamp` as one time | the header declares `uint8_t[8]`, so the pack carries 8 byte keys; its unit and epoch depend on `time_type` |
| `time_interval` in seconds | a raw integer (the header's comment gives a unit of 0.1 microsecond); no shared key has that meaning |
| The state-information push (`LivoxLidarCmdPacket` with command 0x0102) | a key-value list: a 16-bit key count, then a 16-bit reserved word, then the items. The sequential `group … count` reads its count immediately before the items, and the fixed layout has no items of varying length, so the list cannot be stated; see the report's missing additions |
| Command and response packets | the control protocol (`LivoxLidarCmdPacket` with a CRC-16 over its header and a CRC-32 over its data), not data packets |
| `data_type` values the header does not name | no kind: `no-kind` |

## Vectors

`vectors/gen-rt-<kind>.json`: a round trip per kind with two items, values chosen by the
generator and packed by its own serializer from the layouts; `-no-items` has a count of 0.
`gen-err-short` is one byte short of its items, `gen-err-other-id` names no kind.
7 vector files.
