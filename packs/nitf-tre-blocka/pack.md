# Pack: nitf-tre-blocka

The NITF Tagged Record Extension BLOCKA: its CEDATA, 123 characters of fixed
width fields. Public. Generated by `tools/gen/nitfspec2pack.py` from GDAL's
`frmts/nitf/data/nitf_spec.xml` (MIT, commit `fedfd3ec89d6674de030db8f351233f2ee164c30`, sha256 `a4c3c303e91f19543a872dd215ee9d36a30f5445b7f11901c2c0b0068d0eea2c`).
Wire `text` with `delimiter none`: the CEDATA is one field, and each TRE field
is a column `0:<offset>:<length>`. Needs engine version 0.10.

## Message convention

A message is the CEDATA only: the bytes after the 6-character tag (CETAG) and
the 5-digit length (CEL) in the extension area of a NITF header or subheader.
Finding a TRE in that area needs the tag and length of each extension read in
turn, which the pack language cannot state (see the file header pack).

The `text` wire accepts characters 0x20 to 0x7E only. A column's trailing
spaces are removed on decode, and for `int` its leading spaces too; a column
that is then empty is absent, and encode writes spaces there. An `int` column
is written zero-padded to its width. A TRE whose last fields are blank is
written without those trailing spaces.

with a fixed non-blank value is a `const`.

## Shared keys

`lat` and `lon` from `FRFC_LOC` (first row, first column: the image corner (0,0), the first corner of the image subheader's IGEOLO), only in its decimal form `+-dd.dddddd+-ddd.dddddd`, selected by the kinds on its first character (`+` or `-`); in the degrees-minutes-seconds form the kind `frfc-loc-other` binds nothing. Evidence: GDAL `frmts/nitf/nitfimage.c` states that BLOCKA repeats the IGEOLO corner locations at higher precision, and MIL-STD-2500C gives WGS 84 as the default geodetic reference of IGEOLO (ICORDS). The other three corners are raw keys: the model has one position. The kinds require the raw key, so an entity from another format selects none (`no-kind`): the text transforms write no `+`, and the raw key keeps the field's text on a same-format round trip.
